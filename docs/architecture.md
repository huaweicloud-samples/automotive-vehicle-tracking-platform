# 车辆追踪平台架构说明

## 1. 总体架构

本实践在华为云上构建一套「多供应商车辆追踪」参考平台：把碎片化的车辆定位数据源
（GPS / SIM / AIS140 等供应商协议）标准化为统一事件流，对外提供一致的追踪 API。
整体采用「无服务器函数 + 容器工作负载 + 托管中间件」的组合，全部业务组件位于私有子网，
经 APIG 对外暴露 HTTPS 入口。


## 2. 组件职责

| 组件 | 服务 | 职责 |
|---|---|---|
| 入口 API | APIG（专享实例） | 客户端唯一入口，IAM 鉴权，HTTPS 443；经 VPC 通道转发到私有 ELB |
| 流量分发 | 私有 ELB（L7） | 按路径把 `/tracking` 请求分发到两个容器服务（NodePort） |
| 编排服务 | CCE 上的 tracking-connector | 协议标准化、请求路由、响应聚合、会话管理（8080） |
| 订阅管理 | CCE 上的 marketplace-mgmt | 客户关系、认证、供应商配置管理 |
| 供应商适配 | FunctionGraph ×3 | GPS / SIM / AIS140 协议适配，标准化后写入事件总线 |
| 事件总线 | DMS Kafka | 承载位置更新事件流，topic 自动创建，按时间保留 7 天 |
| 会话缓存 | DCS Redis | 低延迟会话状态与热点数据缓存 |
| 规则存储 | DDS 文档数据库（MongoDB 兼容） | 业务规则（policy_rules）、安全规则（security_rules）、会话状态（session_state）三个集合 |
| 镜像仓库 | SWR | 两个容器服务的镜像托管 |
| 加密 | KMS | DMS 盘加密等静态加密主密钥 |
| 日志 | LTS | 函数与工作负载日志，保留 14 天 |

## 3. 网络与安全设计

- **VPC 10.0.0.0/16**，跨两个可用区；公共子网承载 NAT 网关与 APIG 出口，业务全部落在私有子网。
- **公网出口**：IGW（公共子网默认路由）+ 公网 NAT（私有子网 0.0.0.0/0 → NAT）。
- **最小入站**：安全组仅放行必要端口——ELB 8080（VPC 内）、CCE 8080（仅来自 ELB）、
  Kafka 9094 / Redis 6379 / Mongo 8635（仅 VPC 内）、APIG 443（对客户端）。
  出站默认放行（华为云安全组默认行为），无需显式规则。
- **传输与静态加密**：Kafka SASL_SSL + PLAIN、Redis 密码 + SSL、Mongo 密码 + SSL、
  Kafka 盘加密使用 KMS 客户主密钥。

## 4. 关键调用链

1. 供应商（或模拟器）调用 FunctionGraph 适配器（经 APIG 暴露）发起发现/追踪请求。
2. 适配器生成标准化位置事件 → 发布到 DMS Kafka `vehicle-tracking-events`。
3. tracking-connector 消费事件流，结合 Redis 会话与 Mongo 规则做路由、聚合、鉴权。
4. 客户端经 APIG → VPC 通道 → 私有 ELB → 容器服务，查询追踪状态与位置。

## 5. 伸缩与容量

- 容器：CCE 节点横向扩缩（节点池），Deployment 副本数可调（连接器 2、订阅管理 1）。
- 函数：FunctionGraph 按请求自动伸缩，无空闲计费。
- Kafka / Redis / Mongo：托管实例，按规格付费；容量参数在 `infra/variables.tf` 可调。
